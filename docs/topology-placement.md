# Топология и массовое размещение — v0.8.0

## Карта наблюдений

Граф обновляет существующие элементы по стабильным ID, сохраняя их координаты. Полная автораскладка выполняется при первом открытии без сохранённого вида или по кнопке. Новые узлы добавляются рядом с текущим графом; исчезнувшие удаляются. Доступны дерево, сетка, круг и концентрическая раскладка, поиск, масштабирование и fit.

«Сохранить раскладку» сохраняет только координаты в памяти frontend: отдельно для пользователя, фильтра Asset/scope/expired и страницы. Она переживает переходы внутри SPA и переключение граф/таблица. После перезагрузки браузера или выхода из учётной записи исчезает. В backend координаты не записываются; API хранения layout отсутствует. Это не физическое размещение.

Canvas ограничен 500 узлами и 1000 связями, с явным счётчиком пропусков. Дубли ID и связи без доступных концов не отображаются как достоверные объекты. Таблица сохраняет текущую страницу ответа backend. Limit/offset относятся к связям; общего количества сеть API не гарантирует. Truncated/inventory_truncated/observations_truncated видны отдельно.

BMC management relations показываются отдельной таблицей и не превращаются в L2-кабели. TTL/evidence и статус связи берутся из backend, без вычисления физической причины в браузере.

## Партия размещений

Раздел «Размещение» → «Импорт размещений» доступен access.manage. Можно выбрать JSON-файл либо вставить JSON. До 50 строк, до 64 КиБ, одно обоснование партии. Это учётная операция; frontend не двигает оборудование и не отправляет команды Agent.

```json
{
  "placements": [
    {
      "asset_id": "existing_asset_id",
      "mode": "rack",
      "location_id": "existing_rack_id",
      "start_unit": 1,
      "height_units": 1,
      "expected_revision": 0
    }
  ]
}
```

Это шаблон, а не готовые ID стенда. expected_revision — ревизия размещения из GET /api/assets/{id}/placement, не inventory revision. UI требует её явно, даже если API допускает значение по умолчанию. Для outside_rack нужна локация room без юнитов. unplaced явно освобождает размещение: location_id=null, нулевые/отсутствующие юниты, пустая/отсутствующая position. Поле reason файла допускается, но обоснование, отправляемое серверу, берётся из отдельного поля формы.

1. Проверка структуры/UTF-8/диапазонов/дубликатов выполняется до чтения API.
2. Preview читает текущие размещения, локации и rack-layout; одновременно не больше четырёх запросов.
3. Проверяются ревизии, вместимость и пересечения. Старые места всех участников исключаются из проверки итоговой расстановки: атомарная перестановка двух Assets разрешена.
4. Диалог показывает исходные и будущие назначения, имена локаций, ревизии и обоснование. Данные review фиксируются.
5. Только отдельное подтверждение отправляет POST /api/placements/import с Idempotency-Key и CSRF. Поля confirmed в этом контракте нет.
6. Backend повторно проверяет всю партию в транзакции. Ответ 200 содержит фактически сохранённые items. При конфликте подтверждение блокируется; автоматической подмены ревизий и повтора нет. При потере ответа нужно перечитать размещения: операция могла сохраниться.

Локальные unit/browser проверки используют явно simulated данные. Атомарность настоящей БД и конкурентные изменения на живом стенде проверяет интеграционная команда.
