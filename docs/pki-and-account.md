# Сертификаты коллекторов и личный пароль — v0.5.0

## Как открыть

Администратор: меню **Сертификаты коллекторов** (`/security/pki`). Из карточки коллектора есть ссылка с фильтром по Agent UUID. Viewer и Operator не получают управление PKI; прямое открытие страницы не запускает административные GET. Backend окончательно проверяет роль.

Каждый вошедший пользователь: меню **Моя учётная запись** (`/account`). Для смены собственного пароля не нужны административные права.

## Что показывают сертификаты

Список содержит Agent UUID, fingerprint, serial, начало/конец срока, ссылку на предыдущий сертификат и состояние отзыва. Дата проверяется по часам браузера. «Действует по сроку» не означает, что агент подключён: текущее соединение находится в карточке коллектора. Отозванный сертификат всегда показывается отозванным; неизвестные даты не превращаются в действующий сертификат.

Три вкладки запрашивают существующие API:

- `GET /api/pki/certificates` — метаданные сертификатов;
- `GET /api/pki/bootstrap-tokens` — метаданные одноразовых токенов без секретов;
- `GET /api/pki/audit` — серверная история PKI.

Фильтр `agent_id` — канонический ненулевой UUID в нижнем регистре. Лимит — 200 записей. API не предоставляет offset/cursor: интерфейс не обещает полный список при достижении лимита. Можно сузить отбор по конкретному агенту. Активная вкладка обновляет метаданные раз в 30 секунд, скрытая вкладка не получает interval refetch; есть ручное обновление.

## Выдача одноразового токена

1. Нажать **Выдать токен подключения**.
2. Указать согласованный с владельцем агента UUID и срок 60–86 400 секунд. По умолчанию 900 секунд.
3. Проверить UUID и срок в отдельном подтверждении.
4. Выполняется `POST /api/pki/bootstrap-tokens`. Это выдача учётных данных регистрации, а не запуск/перенастройка агента.
5. Секрет доступен только из успешного ответа выдачи. По умолчанию скрыт. Показать или скопировать можно отдельной кнопкой; автоматического копирования нет. Передавать владельцу агента нужно защищённым способом для его настроенной `token_env`.
6. Кнопка **Удалить секрет из формы**, закрытие или уход со страницы убирают его из интерфейса. Серверный токен при этом остаётся выданным до использования, истечения или явного отзыва. Очистка формы не равна отзыву.

Секрет не возвращается из mutation-функции в MutationCache, не сохраняется в query cache, URL, localStorage/sessionStorage или файловый экспорт. Clipboard после явного копирования находится под контролем оператора; интерфейс не обещает стереть его автоматически. Временная память браузера не является защищённым хранилищем.

Этот POST не имеет заявленного Idempotency-Key. Автоматического повтора нет. Если связь пропала, токен мог успеть создаться: закрыть форму, перечитать метаданные, проверить UUID/время и при необходимости отозвать запись. Старое подтверждение после ошибки повторить нельзя. Невосстановимый секрет нельзя получить через GET.

## Отзыв и влияние на агента

Токен: `POST /api/pki/bootstrap-tokens/{id}/revoke`, `{confirmed:true}`. Отзывается только возможность первичной регистрации этим токеном; существующий сертификат не отзывается.

Сертификат: `POST /api/pki/certificates/{fingerprint}/revoke`, `{confirmed:true}`. В подтверждении показаны Agent UUID и точный fingerprint. **Backend закрывает поток агента; для повторного подключения нужен другой действующий сертификат.** Это намеренное действие администратора, а не фоновая часть мониторинга. Страница сама ничего не отзывает.

После успеха перечитываются метаданные и аудит. После ошибки подтверждение блокируется: нужно перечитать состояние и принять новое решение. Успех определяется ответом backend, а не локальным переключением статуса.

При `503 pki_disabled` интерфейс показывает отключённый сервис и не позволяет выдавать токены. Frontend не включает PKI, не генерирует CA, не получает закрытые ключи и не обращается к enrollment endpoint от имени агента. Наличие CA/mTLS и настройки PKI проверяет команда backend/Collector.

## Смена собственного пароля

Пользователь вводит текущий пароль, новый и повтор нового. Новый пароль — минимум 12 символов и максимум 256 байт UTF-8. В подтверждении только имя пользователя, без паролей.

`POST /api/auth/password` передаёт `{current_password,password}` с текущим CSRF. Повтор нужен только браузеру и в запрос не включается. Backend проверяет текущий пароль и завершает все сессии пользователя. После 204 frontend очищает приватный кэш и просит войти заново. При ошибке поля очищаются; автоматического повтора нет. Пароли не помещаются в mutation/query cache или browser storage.

Сброс чужого пароля администратором остаётся отдельной формой в разделе пользователей. Личная форма никогда не вызывает административный endpoint.

## Границы проверки

45 unit/component/API/contract tests и 24 браузерных сценария описаны в `verification.md`. PKI issue/revoke проверены на явно simulated fixtures. Реальные native Backend + PostgreSQL подтвердили отключённую границу PKI, смену собственного пароля, отзыв двух независимых сессий и повторный вход с новым паролем. Выпуск настоящего сертификата CA, enrollment и отключение живого Collector требуют отдельного согласованного стенда.

Исходники Agent и backend не изменялись. В ZIP включён только frontend.
