# Интерфейс и параметры протоколов — v0.9.0

## Навигация, карта и темы

Путь страницы показывает раздел, тип вложенного объекта и ID. Можно вернуться к списку оборудования, источников, коллекторов, локаций, заданий или команд. Симптом и коррелированный случай остаются разными маршрутами. Длинный ID сокращается только визуально; полный доступен в title и карточке.

Карта предоставляет доступный select узла и кнопку показа его окрестности. Это меняет выделение и масштаб, а не координаты. Тёмная/светлая тема применяется к подписям Cytoscape, осям, легендам, линиям сетки и подсказкам ECharts. Семантика unknown/null/0 и разрывы истории сохраняются. Смена темы не запускает раскладку сети.

## Редактор управляемых Targets

Администратор открывает Коллекторы → карточка → Редактировать Targets. Отправляется весь snapshot с исходной expected_revision, CSRF и Idempotency-Key. Просмотр snapshot — отдельный этап. Ответ о сохранении desired не означает applied: применяется существующий workflow backend и Collector.

Общие поля: Target ID, protocol, enabled, endpoint, локальные credential/CA references. Дополнительные параметры раскрываются отдельно. Пустое значение означает отсутствие параметра в JSON; backend выполняет нормализацию фиксированными default. UI не записывает пароли/ключи на Collector и не создаёт references в его локальном allowlist.

| Протокол | Интервалы                                                      | Параметры                                                                                                  |
| -------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| SNMP     | fast/medium/inventory/topology: 3–86400 с; timeout: 0,01–300 с | v2c/v3, port/retries, security level, auth/privacy algorithms, context                                     |
| RouterOS | fast/medium/inventory/topology: 3–86400 с; timeout: 0,01–300 с | HTTPS origin, credential_ref/ca_ref; отдельного options-блока нет                                          |
| SIP      | fast: 3–86400 с; timeout: 0,01–60 с                            | UDP/TCP/TLS, port, From/To/domain, TLS server name/CA, failure/latency thresholds                          |
| Redfish  | medium/inventory: 10–86400 с; timeout: 0,01–300 с              | session/basic, request timeout 0,01–30 с, limits ресурсов/страниц/запросов                                 |
| IPMI     | medium/inventory: 10–86400 с; timeout: 0,01–300 с              | port, cipher 3/17, user/operator, retries, request/session/cache durations, limits SDR/FRU/байтов/операций |

Период 0 или отсутствие выбирает backend default. Hardware fast/topology и SIP medium/inventory/topology не используются. При смене протокола редактор удаляет несовместимые блоки и периоды; для SIP удаляет credential_ref, для non-TLS убирает CA. При возврате SNMP v3 → v2c удаляются auth/privacy/context. TLS SIP выбирает стандартный порт 5061 вместо 5060, сохраняя уже заданный нестандартный порт.

Особенно важно: аппаратный мониторинг использует **medium_interval**, не fast_interval. В v0.9.0 исправлено неверное назначение fast при переключении на Redfish/IPMI. Числовые длительности отправляются в protobuf JSON, например 86400s или 0.25s; строка 5m не интерпретируется браузером как пять секунд.

Клиент помогает найти дубликаты ID, неверные интервалы, несовместимые options и очевидные ошибки endpoint. Ограничения отдельных полей заданы в форме. Окончательная полная проверка, ACL, revision и политика Collector остаются на backend/Collector. После ошибки подтверждение блокируется; автоматического повторного PUT нет.

## Доказательства AI

Связи берутся только из локальной таблицы references, возвращённой backend в preview. Строка refs из ответа модели сама по себе не является URL.

- incident_id открывает исходный симптом.
- asset_ids открывают существующие маршруты карточек Assets.
- correlation_evidence_id открывает конкретное основание только при совпадении с загруженным списком текущего случая.
- signal_id не подменяется incident_id: это разные сущности.
- Неизвестный или неоднозначный ref остаётся текстом «Ссылка не сопоставлена».

У гипотез показана уверенность, у рекомендаций — ограничение read-only/решение оператора. AI не получает кнопки исполнения. Перед отправкой требуется просмотр экспорта и отдельное согласие; истёкший/некорректный preview блокируется повторно перед POST. Подготовка нового preview во время отправки запрещена. При переходе к другому случаю состояние предыдущего анализа сбрасывается.

Проверки выполняются с simulated provider; реальный платный LLM не вызывается.
