# Сценарий просмотра

1. `pnpm dev:demo`; войти `demo / demo`. Убедиться, что видна пометка тестовых данных.
2. Обзор: открытые случаи отдельно от подключений и сессий.
3. Источники → Zabbix: подключение, capabilities и задачи. Это fixtures, не реальный Zabbix.
4. Оборудование → dc-core-01 → Источники и идентичность: Collector и Zabbix у одного Asset.
5. Инвентаризация → частичные поля; hardware → температура и отдельный freshness.
6. На карте → выбрать узел/связь; сравнить граф с таблицей; раскрыть направленные observations.
7. Инциденты → Деградация голосового сервиса → timeline и member symptoms.
8. Логи → поиск `VLAN`; SIP → timeout как null latency, а не 0 мс.
9. Конфигурации → dc-core-01 → actual 30 / expected 20 → причина → создать запрос → открыть запрос → отдельное одобрение → ждать verified. Исполнение в demo — fake Runner.
10. В инциденте AI → просмотреть экспорт → отдельное подтверждение → simulated-provider result. Никакого исполнения из ответа модели.
11. Отчёты → происхождение simulated → distinct episodes/chronic. Demo report — отдельный fixture за период, не сумма текущих карточек.
12. Выйти, войти Viewer → убедиться, что управление недоступно.

Для настоящего стенда использовать `pnpm dev`, реальные users backend и явно подготовленные источники. Текст о действующих интеграциях произносить только после реальной проверки.
